Caso de Estudio Académico — UX/UI

Diseño y Maquetación de Portfolio Web Personal con Enfoque Semántico y Accesible

Documentación técnica y metodológica sobre la construcción de la estructura base para el portfolio personal, respetando nueve secciones requeridas y normas de accesibilidad web sin frameworks.

Rol: Front-End Developer / Diseñador UX/UI
Contexto: Trabajo Final — Licenciatura en Sistemas
Año: [AÑO PROVISIONAL: 2026]
Tecnologías: HTML5 Semántico, CSS3, JavaScript Vanilla

1. Resumen Ejecutivo

El presente proyecto corresponde al desarrollo del portfolio personal para un estudiante de segundo año de la Licenciatura en Sistemas de Información con orientación al desarrollo Front-End. Abarca tanto la Fase 1 (Estructura base y accesibilidad) como la Fase 2 (Personalización visual minimalista, monocromática y editorial).

El principal requerimiento consistió en diseñar y codificar una arquitectura web estática libre de frameworks pesados, aplicando exclusivamente tecnologías estándar del navegador (HTML5, CSS3 y JavaScript vanilla), priorizando la claridad estructural, el sistema de espaciado modular en múltiplos de 8 px, el uso exclusivo de escala monocromática y la accesibilidad universal (WCAG 2.2 AA).

2. El Desafío UX/UI

El desafío principal radicó en organizar una cantidad significativa de contenido estructurado en nueve secciones obligatorias sin sobrecargar cognitivamente al visitante y manteniendo una jerarquía visual armónica tanto en dispositivos móviles (375 px) como en pantallas de escritorio (1280 px).

Restricciones y condiciones clave:

  • No inventar experiencia laboral ni logros que no correspondan al nivel del estudiante (2° año de la carrera).
  • Centralizar estilos y comportamientos en archivos únicos y limpios (styles.css y main.js).
  • Garantizar navegación completa por teclado y soporte para usuarios con preferencias de movimiento reducido.
  • Mantener una estética neutra y provisional que no condicione la futura identidad visual.

3. Objetivos

  • Estructural: Maquetar el documento con etiquetas HTML5 semánticas (header, nav, main, section, article, footer) con un único encabezado de primer nivel (h1).
  • Navegabilidad: Proveer un menú de anclas sticky con opción de navegación móvil hamburguesa accesible con atributos ARIA adecuados (aria-expanded, aria-controls).
  • Adaptabilidad: Implementar un layout móvil-primero utilizando CSS Grid y Flexbox que responda fluidamente en 375 px, 768 px y 1280 px.
  • Extensibilidad: Dejar preparados y debidamente rotulados todos los campos de configuración personal para que el estudiante pueda sustituirlos sin romper la maquetación.

4. Arquitectura de Información

La estructura de información fue organizada de forma lineal y progresiva para guiar al evaluador desde la presentación general hasta los medios de contacto:

  1. 01. Header / Navigation: Identidad, accesos directos por ancla a las 9 secciones y enlace a GitHub.
  2. 02. Hero: Presentación clara del estudiante, objetivo profesional, estado de disponibilidad y llamadas a la acción primarias.
  3. 03. Métricas: Cuatro tarjetas cuantitativas con datos académicos provisionales para dimensionar el progreso.
  4. 04. Skills: Categorización técnica en Front-End, Programming y Tools para ordenar el perfil de competencias.
  5. 05. Projects: Tarjetas con mockups, tecnologías, resultados académicos y enlaces a código y caso de estudio.
  6. 06. Experience / Education: Línea de tiempo que refleja la formación universitaria y deja espacio reservado para futuras prácticas laborales.
  7. 07. About Me: Perfil personal, fotografía, idiomas y tres principios fundamentales de trabajo.
  8. 08. Contact: Múltiples canales directos (Email, LinkedIn, GitHub) y maqueta de formulario demostrativo.
  9. 09. Footer: Créditos técnicos, copyright y repetición de navegación para facilitar el retorno.

5. Implementación Técnica

Para mantener la máxima performance y pureza técnica, no se incorporaron dependencias de terceros ni frameworks CSS como Bootstrap o Tailwind. Las decisiones técnicas se basaron en:

  • Variables CSS (Custom Properties): Se definió una paleta neutra en :root basada en tonos pizarra (slate), permitiendo modificar la temática en una única línea de código en fases posteriores.
  • Scroll suave con compensación: Se utilizó scroll-behavior: smooth complementado con scroll-margin-top: 5rem en cada sección con identificador para evitar que el header fijo oculte los encabezados.
  • Enlace de salto (Skip-link): Se incluyó un enlace accesible al inicio del cuerpo para que usuarios de teclado y lectores de pantalla puedan saltar directamente al contenido principal sin recorrer toda la barra de navegación.
  • Media queries de accesibilidad: Implementación de @media (prefers-reduced-motion: reduce) para respetar las preferencias de usuarios con sensibilidad a animaciones.

6. Resultados y Aprendizajes

La finalización de esta primera fase permitió validar los siguientes puntos:

Dominio de Estándares Web

Construir un sitio completo sin apoyarse en frameworks refuerza el entendimiento profundo del modelo de cajas, el apilamiento (z-index) y el DOM nativo.

Criterio UX en Contenido

Aprender a comunicar con honestidad un perfil formativo de estudiante universitario sin inflar datos ni inventar experiencia laboral inexistente.

Mantenibilidad Modular

La separación estricta en HTML, CSS y JS garantiza que la incorporación de la identidad visual definitiva en la Fase 2 sea ágil y predecible.

7. Próximos Pasos

Con la estructura base completada y testeada, las siguientes etapas del proyecto incluirán:

  • Definición de identidad visual y tipografía de acento.
  • Incorporación de fotografías reales del estudiante y capturas definitivas de proyectos.
  • Pruebas de usabilidad con usuarios finales en la cátedra de UX/UI.
